# Stripe決済付き 基本的なECサイト

これは、Node.js, Express, Stripe Checkout を使用して構築された、シンプルなECサイトのサンプルアプリケーションです。

## 概要

このアプリケーションは、いくつかの商品をリスト表示し、ユーザーが商品をショッピングカートに追加して、まとめて支払いを行うことができる基本的なEC機能のデモンストレーションです。

## 主な機能

-   サーバーから動的に商品リストを読み込んで表示
-   ショッピングカート機能（商品の追加、数量変更、削除）
-   **在庫管理機能**
    -   在庫数に基づいた「売り切れ」表示
    -   決済前の在庫確認
    -   決済完了後の自動在庫削減 (Stripe Webhook利用)
-   カート内の複数商品をまとめて決済できるStripe Checkout連携
-   決済成功時・キャンセル時の結果表示ページ

## 技術スタック

-   **バックエンド**: Node.js, Express
-   **決済処理**: Stripe API (Checkout, Webhooks)
-   **フロントエンド**: HTML, CSS, JavaScript (ES6, localStorage)
-   **その他**: `dotenv` (環境変数管理)

## セットアップと実行方法

### 1. 前提条件

-   [Node.js](https://nodejs.org/) (v14以降を推奨)
-   [Stripe](https://stripe.com/) アカウント
-   [Stripe CLI](https://stripe.com/docs/stripe-cli) (ローカルでのWebhookテストに必要)

### 2. インストール

まず、このリポジトリをクローンします。

```bash
git clone https://github.com/your-username/basic-ec-with-stripe.git
cd basic-ec-with-stripe
```

次に、必要なnpmパッケージをインストールします。

```bash
npm install
```

### 3. 環境設定

StripeのAPIキーとWebhookシークレットを設定する必要があります。プロジェクトのルートディレクトリに `.env` という名前のファイルを作成し、以下のように記述してください。

```
# Stripeのテスト環境用シークレットキー
STRIPE_SECRET_KEY=sk_test_YOUR_SECRET_KEY

# Stripe CLIで取得したWebhook署名シークレット
STRIPE_WEBHOOK_SECRET=whsec_...
```

-   `STRIPE_SECRET_KEY`: ご自身のStripeテスト環境のシークレットキーに置き換えてください。キーは[Stripeダッシュボード](https://dashboard.stripe.com/test/apikeys)で確認できます。
-   `STRIPE_WEBHOOK_SECRET`: ローカルでのテスト時にStripe CLIを実行するとターミナルに表示されるキーです（後述）。

### 4. アプリケーションの起動とテスト

**1. サーバーの起動**

まず、以下のコマンドでWebサーバーを起動します。

```bash
npm start
```

コンソールに `Server is running on port 3000` と表示されれば成功です。ブラウザで `http://localhost:3000` にアクセスできます。

**2. Webhookの転送 (別のターミナルで実行)**

決済完了後の在庫削減機能をテストするには、Stripeからの通知をローカルサーバーに転送する必要があります。別のターミナルを開き、以下のコマンドを実行してください。

```bash
stripe listen --forward-to localhost:3000/webhook
```

このコマンドを実行すると、`whsec_...`で始まる**Webhook署名シークレット**がターミナルに表示されます。これをコピーし、`.env`ファイルの`STRIPE_WEBHOOK_SECRET`に設定してください。

## アプリケーションの仕組み

1.  **商品表示**: ユーザーがトップページにアクセスすると、フロントエンドは `/api/products` を呼び出し、商品情報を取得します。在庫がゼロの商品は「売り切れ」と表示されます。
2.  **カートへの追加**: ユーザーが「カートに入れる」ボタンをクリックすると、商品はブラウザの`localStorage`に保存されているカートに追加されます。
3.  **カートの確認**: ユーザーはカートページで、カート内の商品、数量、合計金額を確認・変更できます。
4.  **決済開始と在庫チェック**: ユーザーが「決済に進む」ボタンをクリックすると、フロントエンドはカート情報を `/create-checkout-session` エンドポイントに送信します。バックエンドサーバーはまず、**商品の在庫が十分にあるかを確認します。**
5.  **Checkoutセッション作成**: 在庫に問題がなければ、サーバーはStripe APIを呼び出して決済セッションを作成し、その際に`metadata`にカート情報を保存します。
6.  **リダイレクトと決済**: サーバーは作成されたセッションのURLをフロントエンドに返し、ユーザーをStripeの決済ページにリダイレクトします。
7.  **在庫更新 (Webhook)**: ユーザーが決済を完了すると、Stripeは `checkout.session.completed` イベントをサーバーの `/webhook` エンドポイントに送信します。サーバーはリクエストの署名を検証し、`metadata`からカート情報を復元して、購入された商品の在庫を減らします。
8.  **決済完了ページへの遷移**: ユーザーはStripeの決済ページから `success.html` にリダイレクトされます。



## アプリケーション内容の総括

これまでの調査で、アプリケーションの全体像が把握できました。

このプロジェクトは**「Node.jsとSQLiteで構築された、Stripe連携の基本的なECサイト」**です。

**主な処理の流れは以下の通りです。**

1.  **商品表示**: ユーザーがトップページにアクセスすると、サーバーはデータベースから商品情報を取得して表示します。在庫切れの商品は購入できません。
2.  **カート管理**: ユーザーが商品を選ぶと、その情報はブラウザの`localStorage`（ローカルストレージ）に保存されます。カートページでは内容の確認や変更ができます。
3.  **決済開始**: ユーザーが決済に進むと、サーバーはまずデータベースで在庫を確認します。
4.  **Stripe連携**: 在庫が十分にあれば、サーバーはStripeに決済情報を作成させ、ユーザーを安全なStripeの決済ページに移動させます。
5.  **在庫の自動更新**: ユーザーが決済を完了すると、Stripeからサーバーに通知が届きます。サーバーはその通知を受けて、データベース上の商品在庫を自動で減らします。

このように、フロントエンド（ブラウザ）、バックエンド（サーバー）、決済サービス（Stripe）が連携して動作する、実践的なECサイトのサンプルとなっています。

## 主なアーキテクチャ変更

### 商品管理機能のデータベース化 (2025/12/01実施)

アプリケーションの運用性と拡張性を向上させるため、商品データの管理方法をサーバーのメモリ上の配列からSQLiteデータベースに移行しました。

**目的:**
- **運用性の向上:** ソースコードを直接編集することなく、商品の追加や更新ができる基盤を整備。
- **データの永続化:** 在庫数の変更などがサーバーを再起動しても失われないようにする。
- **拡張性の確保:** 将来的な管理者向け機能などの追加を容易にする。

**主な変更点:**
1.  **データベース導入:**
    *   `sqlite3` を導入し、商品データを永続化するためのデータベースファイル (`database/database.db`) を使用するように変更。
    *   データベース接続やクエリ実行を抽象化するモジュール (`database/db.js`) を作成。

2.  **テーブル作成と初期データ投入:**
    *   `products`テーブルを定義し、アプリケーションの初回起動時にテーブル作成と初期データ投入を行うスクリプト (`database/init.js`) を追加。

3.  **サーバーロジックの修正 (`server.js`):**
    *   **商品取得:** `/api/products`エンドポイントが、データベースから商品リストを取得するように修正。
    *   **在庫チェック:** `/create-checkout-session`エンドポイントが、データベースに在庫数を問い合わせてから決済セッションを作成するように修正。
    *   **在庫更新:** `/webhook`エンドポイントが、決済完了通知に応じてデータベースの在庫数を更新するように修正。トランザクション処理も導入。
